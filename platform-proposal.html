01

The question we hear most often

Can I still edit my own website?

Yes — and you'll have more tools than before.

The new platform includes a full visual editor. You see your live site on screen while you edit. Click any section to open its fields and update your content. Most clients are comfortable editing independently within an hour of onboarding.

Current WordPress + Bricks Builder
  • Visual drag-and-drop editor
  • Live preview while editing
  • Inline text editing
  • Image uploads and media library
  • Freeform layout editing can accidentally break your design
  • Plugin or WordPress updates can cause unexpected site issues
  • No version history or content rollback
  • No draft / review / approval workflow
  • No native scheduled publishing
New platform Storyblok + Astro
  • Visual editor with your live site in view
  • Click any section or component to open and edit its fields
  • Drag to reorder sections and content blocks on any page
  • Add new sections from an approved, pre-designed component library
  • Image uploads, media library, and automatic image optimization
  • Preview across desktop, tablet, and mobile before publishing
  • Full version history — restore any prior version in one click
  • Draft → Review → Publish content approval workflow
  • Schedule content to go live at a specific date and time
  • Layouts are structurally protected — your design cannot be accidentally broken

One meaningful difference worth understanding: in the new system, page layouts live inside developer-built components. You edit the content inside those components freely — text, images, CTAs, entire sections — but the underlying design structure stays intact. This means no accidental layout breaks, and no late-night support calls when a section gets pushed out of alignment.

Speed & search performance

A dramatically faster website, by default.

WordPress generates pages dynamically — every visitor triggers a PHP request, a database query, and an assembly process on the server. The new platform pre-builds every page as clean HTML before anyone visits, then serves it from a global CDN. The result is a consistently fast experience, for every visitor, everywhere in the world.

The business case

Why this investment pays for itself.

Performance drives real revenue
Google ranks faster sites higher in search results. Faster load times directly reduce bounce rates and increase conversions. These performance gains are structural and permanent — not the result of ongoing optimization work.
Faster turnaround on every update

Platform & plan requirements
  • Storyblok Free works for demos and dev — limited to 1 user and no approval workflow
  • Storyblok Team (~$100/mo) is the minimum for a live client site — includes version history, full workflow, multiple users, and scheduling
  • Netlify Free tier is sufficient for most small–medium sites; Pro (~$19/mo/member) adds password protection, analytics, and build concurrency
  • Compare total stack cost to WP Engine Business + security plugins + retainer time for patches — usually comparable or lower at Team tier
Self-serve vs. dev request: honest breakdown
  • Self-serve: all text, images, CTAs, links, adding/removing/reordering blocks within a page, publishing, scheduling, rollback
  • Dev request: new component types, layout changes, new page templates, animation or interaction changes, structural redesigns
  • This scope is effectively identical to WP — clients could always edit content but not build new layouts anyway
  • Key differentiator: Storyblok makes self-serve less scary because editors literally cannot break the structure
Realistic timeline estimates
  • Component library build: 2–3 weeks (one-time investment, reusable across all future client builds)
  • Content migration: 1–3 days depending on page count and content complexity
  • Typical full project: 4–8 weeks for a 10–20 page site
  • Subsequent clients using the same component system: significantly faster — estimate 1–2 weeks for build + migration
  • Frame the upfront cost as an investment in the system, not in a single site
Anticipated objections + responses
"What if Storyblok goes away?"
Content is stored as structured JSON delivered via API — it's portable. Astro can connect to any headless CMS. Content isn't locked in the way a WordPress database is.
"We're used to WordPress."
Storyblok's visual editor is genuinely intuitive. One onboarding session is typically enough. Most editors actually prefer it because they can't accidentally break anything.
"This sounds more expensive upfront."
Initial build is comparable. Ongoing is typically lower — no security retainer, faster change requests, no emergency plugin-break recovery. Frame it as front-loaded with reduced long-term cost.
"What happens to our existing SEO rankings?"
URL structure is preserved. Sitemaps, canonical tags, and redirects are all handled during migration. Performance improvements typically lift rankings — not hurt them.
"We can't add a completely new layout section ourselves?"
Correct — that's a dev request, same as it always has been. They couldn't build new layout types in WordPress either. Reframe: the component library is designed upfront to cover every section type they'll need.
Strongest talking points by audience
  • Business owner / decision-maker: performance = more conversions, lower ongoing maintenance cost, better Google rankings
  • Marketing team: version history, scheduling, approval workflow, faster turnaround on campaign pages
  • Technical stakeholder: no PHP vulnerabilities, CDN delivery, 90+ Lighthouse, CI/CD quality gates on every deploy
  • Cautious or reluctant editor: "you literally cannot break the layout" removes the anxiety of self-editing entirely — lead with this
